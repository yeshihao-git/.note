# 消息总线 EventBus

核心是**发布 - 订阅（Pub/Sub）**：

1. 总线维护一张 `事件名 = 回调函数数组` 的映射表
2. 发送方：`bus.emit('事件名', 参数)` 广播
3. 接收方：`bus.on('事件名', 回调)` 提前注册监听
4. 发送者不知道谁会接收，接收者不知道谁发送，完全解耦
    
    典型特征：**监听可以分散在任意组件，随时订阅 / 取消订阅**。


# v-model

**父组件**：
```vue
<MyCheckbox v-model="checked" />
```
v-model 是语法糖，vue 会自动编译为以下内容
```vue
<MyCheckbox
  :modelValue="checked"
  @update:modelValue="checked = $event"
/>
```

**子组件**：
必须接收
```vue
defineProps({
  modelValue: Boolean
})
```
并且触发
```vue
emit('update:modelValue', 新值)
```

**为什么发送事件名为 update:modelValue** ？
vue 规定
```vue
update:prop名
```
例如
```vue
# 父组件
<MyComponent
  :name="name"
  :age="age"
  :sex="sex"
/>

# 子组件
emit('update', value) 则 vue 不知道更新的是 name、age、sex

# 正确 子组件
emit('update:name', 'Tom')
emit('update:age', 18)
emit('update:sex', '男')
```
而 vue 默认把 v-model 绑定到 modelValue，所以默认事件就是 update:modelValue


# vtk.js pipeline

**why**：
下游依赖上游，当上游变化，下游能感知到，vtk 会自动沿着 pipeline 进行计算
## pipeline 写法

VTK/vtk.js 的 Pipeline 写法 **起点几乎都是 `setInputData()`**，然后后面的 Filter 都通过 **`setInputConnection()` + `getOutputPort()`** 串起来

标准写法就是：

```text
vtkPolyData
      │
setInputData()
      │
TriangleFilter
      │
getOutputPort()
      │
setInputConnection()
      │
ClipFilter
      │
getOutputPort()
      │
setInputConnection()
      │
Normals
      │
getOutputPort()
      │
setInputConnection()
      │
Mapper
      │
Actor
```

对应代码就是：

```js
// 数据源
const triangleFilter = vtkTriangleFilter.newInstance();
triangleFilter.setInputData(polyData);

// Filter1 -> Filter2
const clipper = vtkClipPolyData.newInstance();
clipper.setInputConnection(triangleFilter.getOutputPort());

// Filter2 -> Mapper
const mapper = vtkMapper.newInstance();
mapper.setInputConnection(clipper.getOutputPort());

// Mapper -> Actor
const actor = vtkActor.newInstance();
actor.setMapper(mapper);
```

---

### 为什么第一个必须是 `setInputData()`？

因为 `polyData` 已经是**数据本身**了。

例如：

```js
const polyData = reader.getOutputData();
```

`polyData` 是一个 `vtkPolyData` 对象。

所以：

```js
triangleFilter.setInputData(polyData);
```

是正确的。

---

### 为什么后面都是 `setInputConnection()`？

因为：

```js
triangleFilter.getOutputPort()
```

返回的是：

```text
vtkAlgorithmOutput
```

它不是数据，而是：

> **"如果有人需要数据，就从我这里取。"**

所以：

```js
clipper.setInputConnection(
    triangleFilter.getOutputPort()
);
```

就是告诉 `clipper`：

> **你的输入来自 `triangleFilter` 的输出。**

---

### 那什么时候用 `getOutputData()`？

只有当你真的想**把 Pipeline 截断**的时候。

例如：

```js
clipper.update();

const polyData = clipper.getOutputData();
```

这时候：

```text
Pipeline
      ↓
vtkPolyData
```

后面的 Mapper 就不知道：

```text
这个 PolyData 是 Clip 出来的
```

只能：

```js
mapper.setInputData(polyData);
```

---

### 一句话总结

可以记住这个规律：

> **已有数据 → `setInputData()`**
>
> **连接上游算法 → `setInputConnection()`**

对应关系如下：

| 输入类型                     | 使用方法                   |
| ------------------------ | ---------------------- |
| `vtkPolyData`            | `setInputData()`       |
| `vtkImageData`           | `setInputData()`       |
| `vtkUnstructuredGrid`    | `setInputData()`       |
| `filter.getOutputPort()` | `setInputConnection()` |
| `reader.getOutputPort()` | `setInputConnection()` |

# 类似 vtkjs 这种 api 文档全的库，如何查看具体信息

例如：`const config = vtkAxesActor.getConfig();` 使用时发现有智能提示 `config.recenter`，如何知道 config 中还有哪些字段？

## 方法1：debug

终端中启动 vite 服务器，在 launch.json 中将端口改到和 vite 服务器一致，开始 debug
1. 直接鼠标悬浮查看
2. 调试控制台中输入 `axesActor.getConfig()`

## 方法2：看源码

在头文件 `import vtkAxesActor from '@kitware/vtk.js/Rendering/Core/AxesActor';` 中右键选中==转到源定义==（不是转到类型定义）

发现 `defaultValues` 函数定义了 `config` 的默认结构：

```js
config: {
  recenter: true,        // ← 就在这里
  tipResolution: 60,
  tipRadius: 0.1,
  tipLength: 0.2,
  shaftResolution: 60,
  shaftRadius: 0.03,
  invert: false,
  ...initialValues?.config
}
```

所以 `getConfig()` 返回的 `config` 对象包含以下字段：

| 字段 | 默认值 | 含义 |
|------|--------|------|
| `recenter` | `true` | 是否将轴居中（true=原点在中间，false=原点在一端） |
| `tipResolution` | `60` | 箭头尖端分辨率 |
| `tipRadius` | `0.1` | 箭头尖端半径 |
| `tipLength` | `0.2` | 箭头尖端长度 |
| `shaftResolution` | `60` | 箭杆分辨率 |
| `shaftRadius` | `0.03` | 箭杆半径 |
| `invert` | `false` | 是否反转方向 |

同理，`xConfig` / `yConfig` / `zConfig` 各自包含 `color` 和 `invert` 字段。

## 方法 3：打印

```js
const config = axesActor.getConfig();
console.log(config);
```

后续在浏览器的控制台日志中查看，若 trae 开启调试模式，则能在 调试控制台 查看

# VTK.js 模型平移时被"切开"的问题

### 问题
使用 TransformControlsWidget 平移模型到一定距离后，模型出现被平面截断的现象，看起来像被刀切开。

### 原因
VTK.js 相机有 **near/far clipping plane**（近/远裁剪面），只有在 `[near, far]` 范围内的物体才会被渲染。默认的 clipping range 是在初始化时根据场景计算的，当模型通过 `actor.setPosition()` 平移到远离原始位置时，超出了 far clipping plane 的范围，超出部分就会被裁剪掉，表现为模型被"切开"。

### 解决方法
在模型位置发生变化的回调中，调用 `renderer.resetCameraClippingRange()` 重新计算裁剪范围：

```js
transform.onModified((state) => {
  actor.setPosition(state.getTranslation());
  actor.setScale(state.getScale());
  actor.setOrientationFromQuaternion(state.getRotation());
  renderer.resetCameraClippingRange(); // 关键：重新计算裁剪范围
});
```

该方法会遍历场景中所有 actor 的 bounding box，重新计算合适的 near/far 值，确保模型始终在可见范围内。

# resetCameraClippingRange()

是 vtk.js 中一个非常常用的函数，它的作用是：

> **根据当前场景中所有可见 Actor 的空间范围，重新计算 Camera 的 near/far clipping range（近裁剪面和远裁剪面）。**

简单说：
`resetCameraClippingRange()` 是重新计算相机的**视锥体深度方向范围（near clipping plane 和 far clipping plane）**，确保当前场景中的可见物体落在这个深度范围内，不会因为超出 near/far 而被裁剪掉。

---

## 1. 先理解 Camera 的 clipping range

三维相机不是无限远地看东西，它有两个限制：

```
Camera

    |
    |
    | near clipping plane
    |
    |
    |       Object
    |
    |
    | far clipping plane
```

也就是：

```text
near ---------------- far

    可见区域
```

只有在这个范围内的物体才会被渲染。

在 vtk.js 中：

```javascript
camera.getClippingRange()
```

例如：

```javascript
[
  0.1,
  1000
]
```

表示：

```
最近 0.1 单位
最远 1000 单位
```

---

## 2. 为什么需要 resetCameraClippingRange？

假设：

你加载一个模型：

```javascript
renderer.addActor(actor);
```

然后：

```javascript
renderer.resetCamera();
```

相机可能移动到了正确位置。

但是：

clipping range 还是旧的。

比如：

之前：

```
模型大小:

0 ~ 10
```

后来加载：

```
模型大小:

0 ~ 100000
```

相机：

```
near=0.1
far=100
```

结果：

```
100以外的部分被裁掉
```

你看到：

* 模型缺失
* 剖切后消失
* 放大缩小时闪烁

这时候：

```javascript
renderer.resetCameraClippingRange();
```

重新计算：

```
near=10
far=200000
```

问题解决。

---

## 3. 它和 resetCamera 的区别

很多初学者容易混淆。

### resetCamera()

作用：

> 调整相机位置和方向，使整个场景进入视野

例如：

```javascript
renderer.resetCamera();
```

改变：

* camera position
* focal point
* view angle

例如：

原来：

```
camera

     *
      \
       \
        object
```

reset 后：

```
camera

    *
     \
      object
```

---

### resetCameraClippingRange()

作用：

> 不移动相机，只调整可见深度范围

例如：

之前：

```
camera

near
 |
 |
object
 |
far
```

调整：

```
camera

near
   |
   |
object
   |
far
```

相机位置不变。

---

## 5. 剖切操作中为什么经常调用？

结合你之前做的：

```text
vtkClipPolyData

    ↓

Mapper

    ↓

Actor
```

比如：

原模型：

```
████████
████████
████████
```

裁剪后：

```
████
████
```

模型 bounds 变化。

但是 Camera 还是按照旧范围：

```
far 太大
near 太小
```

可能导致：

* 深度精度下降
* 闪烁(z-fighting)
* 小模型消失

所以：

```javascript
clipper.update();

renderer.resetCameraClippingRange();

renderWindow.render();
```

很常见。

## 6. vtk.js 源码层面大概做什么？

内部逻辑类似：

```javascript
const bounds = computeVisiblePropBounds();


camera.computeClippingRange(
    bounds
);
```

也就是：

1. 遍历 renderer 中所有 prop

类似：

```javascript
renderer.getActors()
```

2. 获取 bounds：

```javascript
actor.getBounds()
```

例如：

```javascript
[
 xmin,
 xmax,
 ymin,
 ymax,
 zmin,
 zmax
]
```

3. 根据 camera 方向计算：

```
near
far
```

4. 设置：

```javascript
camera.setClippingRange(
    near,
    far
);
```

---

## 7. 什么时候必须调用？

比较重要：

| 情况                | 需要吗   |
| ----------------- | ----- |
| 第一次加载模型           | ✅需要   |
| 添加新 Actor         | ✅建议   |
| 删除大模型             | ✅建议   |
| vtkClipPolyData 后 | ✅建议   |
| Camera旋转          | ❌通常不用 |
| Camera平移          | ❌不用   |
| 改变Actor颜色         | ❌不用   |

所以一句话总结：

> `resetCameraClippingRange()` 不负责“把模型放到屏幕中央”，它只负责让相机的 near/far 范围适配当前场景，保证模型不会因为裁剪范围设置不合理而消失或出现深度问题。

在你现在做的 **vtkClipPolyData + Widget 平面控制剖切** 场景里，它会非常常用。

## 问题类型：深度缓冲（Depth Buffer）渲染优先级问题

### 问题分析
模型和控制球手柄在 3D 空间中位置重叠时，GPU 深度测试会根据 z 值决定谁覆盖谁。模型的面片与控制球手柄深度值接近时，模型赢得了深度测试，导致模型覆盖控制球。
