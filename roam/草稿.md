# 消息总线 EventBus

核心是**发布 - 订阅（Pub/Sub）**：

1. 总线维护一张 `事件名 = 回调函数数组` 的映射表
2. 发送方：`bus.emit('事件名', 参数)` 广播
3. 接收方：`bus.on('事件名', 回调)` 提前注册监听
4. 发送者不知道谁会接收，接收者不知道谁发送，完全解耦
    
    典型特征：**监听可以分散在任意组件，随时订阅 / 取消订阅**。


# v-model

**父组件**：
```vue
<MyCheckbox v-model="checked" />
```
v-model 是语法糖，vue 会自动编译为以下内容
```vue
<MyCheckbox
  :modelValue="checked"
  @update:modelValue="checked = $event"
/>
```

**子组件**：
必须接收
```vue
defineProps({
  modelValue: Boolean
})
```
并且触发
```vue
emit('update:modelValue', 新值)
```

**为什么发送事件名为 update:modelValue** ？
vue 规定
```vue
update:prop名
```
例如
```vue
# 父组件
<MyComponent
  :name="name"
  :age="age"
  :sex="sex"
/>

# 子组件
emit('update', value) 则 vue 不知道更新的是 name、age、sex

# 正确 子组件
emit('update:name', 'Tom')
emit('update:age', 18)
emit('update:sex', '男')
```
而 vue 默认把 v-model 绑定到 modelValue，所以默认事件就是 update:modelValue


# vtk.js pipeline

**why**：
下游依赖上游，当上游变化，下游能感知到，vtk 会自动沿着 pipeline 进行计算
## pipeline 写法

VTK/vtk.js 的 Pipeline 写法 **起点几乎都是 `setInputData()`**，然后后面的 Filter 都通过 **`setInputConnection()` + `getOutputPort()`** 串起来

标准写法就是：

```text
vtkPolyData
      │
setInputData()
      │
TriangleFilter
      │
getOutputPort()
      │
setInputConnection()
      │
ClipFilter
      │
getOutputPort()
      │
setInputConnection()
      │
Normals
      │
getOutputPort()
      │
setInputConnection()
      │
Mapper
      │
Actor
```

对应代码就是：

```js
// 数据源
const triangleFilter = vtkTriangleFilter.newInstance();
triangleFilter.setInputData(polyData);

// Filter1 -> Filter2
const clipper = vtkClipPolyData.newInstance();
clipper.setInputConnection(triangleFilter.getOutputPort());

// Filter2 -> Mapper
const mapper = vtkMapper.newInstance();
mapper.setInputConnection(clipper.getOutputPort());

// Mapper -> Actor
const actor = vtkActor.newInstance();
actor.setMapper(mapper);
```

---

### 为什么第一个必须是 `setInputData()`？

因为 `polyData` 已经是**数据本身**了。

例如：

```js
const polyData = reader.getOutputData();
```

`polyData` 是一个 `vtkPolyData` 对象。

所以：

```js
triangleFilter.setInputData(polyData);
```

是正确的。

---

### 为什么后面都是 `setInputConnection()`？

因为：

```js
triangleFilter.getOutputPort()
```

返回的是：

```text
vtkAlgorithmOutput
```

它不是数据，而是：

> **"如果有人需要数据，就从我这里取。"**

所以：

```js
clipper.setInputConnection(
    triangleFilter.getOutputPort()
);
```

就是告诉 `clipper`：

> **你的输入来自 `triangleFilter` 的输出。**

---

### 那什么时候用 `getOutputData()`？

只有当你真的想**把 Pipeline 截断**的时候。

例如：

```js
clipper.update();

const polyData = clipper.getOutputData();
```

这时候：

```text
Pipeline
      ↓
vtkPolyData
```

后面的 Mapper 就不知道：

```text
这个 PolyData 是 Clip 出来的
```

只能：

```js
mapper.setInputData(polyData);
```

---

### 一句话总结

可以记住这个规律：

> **已有数据 → `setInputData()`**
>
> **连接上游算法 → `setInputConnection()`**

对应关系如下：

| 输入类型                     | 使用方法                   |
| ------------------------ | ---------------------- |
| `vtkPolyData`            | `setInputData()`       |
| `vtkImageData`           | `setInputData()`       |
| `vtkUnstructuredGrid`    | `setInputData()`       |
| `filter.getOutputPort()` | `setInputConnection()` |
| `reader.getOutputPort()` | `setInputConnection()` |

# 类似 vtkjs 这种 api 文档全的库，如何查看具体信息

例如：`const config = vtkAxesActor.getConfig();` 使用时发现有智能提示 `config.recenter`，如何知道 config 中还有哪些字段？

## 方法1：debug

终端中启动 vite 服务器，在 launch.json 中将端口改到和 vite 服务器一致，开始 debug
1. 直接鼠标悬浮查看
2. 调试控制台中输入 `axesActor.getConfig()`

## 方法2：看源码

在头文件 `import vtkAxesActor from '@kitware/vtk.js/Rendering/Core/AxesActor';` 中右键选中==转到源定义==（不是转到类型定义）

发现 `defaultValues` 函数定义了 `config` 的默认结构：

```js
config: {
  recenter: true,        // ← 就在这里
  tipResolution: 60,
  tipRadius: 0.1,
  tipLength: 0.2,
  shaftResolution: 60,
  shaftRadius: 0.03,
  invert: false,
  ...initialValues?.config
}
```

所以 `getConfig()` 返回的 `config` 对象包含以下字段：

| 字段 | 默认值 | 含义 |
|------|--------|------|
| `recenter` | `true` | 是否将轴居中（true=原点在中间，false=原点在一端） |
| `tipResolution` | `60` | 箭头尖端分辨率 |
| `tipRadius` | `0.1` | 箭头尖端半径 |
| `tipLength` | `0.2` | 箭头尖端长度 |
| `shaftResolution` | `60` | 箭杆分辨率 |
| `shaftRadius` | `0.03` | 箭杆半径 |
| `invert` | `false` | 是否反转方向 |

同理，`xConfig` / `yConfig` / `zConfig` 各自包含 `color` 和 `invert` 字段。

## 方法 3：打印

```js
const config = axesActor.getConfig();
console.log(config);
```

后续在浏览器的控制台日志中查看，若 trae 开启调试模式，则能在 调试控制台 查看
