# 软件需求与设计文档

```
			需求
			 │
			 ▼
			PRD
	  ┌──────┴──────┐
	  ▼             ▼
   US + AC       其他需求
	  │
	  ▼
     SPEC
	  │
	  ▼
   设计文档
	  │
	  ▼
	 代码
```

## PRD（产品需求文档）

**what**：PRD
产品需求文档（业务需求），侧重业务与用户价值，它回答 what 和 why

**how**：
US（用户故事） + AC（验收标准）+ 其他

```
PRD
├── 1. 背景 / 问题
├── 2. 目标
├── 3. 用户角色
├── 4. 功能范围
│
├── 5. User Stories（US）
│   ├── US-001 用户登录
│   ├── US-002 用户退出
│   └── US-003 ...
│
├── 6. Acceptance Criteria（AC）
│   ├── US-001 的 AC
│   ├── US-002 的 AC
│   └── ...
│
├── 7. 非功能需求
└── 8. 范围 / 限制
```

## SPEC（规格说明书）

**what**：Spec
规格说明书（功能规格），侧重技术与实现逻辑，它回答 how

## 设计文档

| 关键词                       | 主要回答什么问题        |   是否重要 |
| ------------------------- | --------------- | -----: |
| **Background 背景**         | 为什么要做？          |    ⭐⭐⭐ |
| **Goal 目标**               | 做完以后达到什么效果？     |    ⭐⭐⭐ |
| **Scope 范围**              | 做什么、不做什么？       |    ⭐⭐⭐ |
| **Requirement 需求**        | 系统需要满足什么？       |   ⭐⭐⭐⭐ |
| **Architecture 架构**       | 整体系统怎么组成？       |  ⭐⭐⭐⭐⭐ |
| **Module 模块**             | 系统拆成哪些模块？       |  ⭐⭐⭐⭐⭐ |
| **Flow 流程**               | 数据/业务怎么流转？      |  ⭐⭐⭐⭐⭐ |
| **Data 数据模型**             | 数据怎么存？表怎么设计？    |  ⭐⭐⭐⭐⭐ |
| **API 接口**                | 模块之间怎么通信？       |   ⭐⭐⭐⭐ |
| **Design Decision 设计决策**  | 为什么这样设计？        |  ⭐⭐⭐⭐⭐ |
| **Error 异常**              | 出问题怎么办？         |   ⭐⭐⭐⭐ |
| **Security 安全**           | 怎么认证、授权、保护数据？   |   ⭐⭐⭐⭐ |
| **Performance 性能**        | 性能瓶颈和指标是什么？     |    ⭐⭐⭐ |
| **Concurrency 并发**        | 多人/多请求同时操作怎么办？  |   ⭐⭐⭐⭐ |
| **Transaction 事务**        | 如何保证数据一致性？      |   ⭐⭐⭐⭐ |
| **Logging 日志**            | 出问题怎么排查？        |    ⭐⭐⭐ |
| **Monitoring 监控**         | 怎么发现系统异常？       |    ⭐⭐⭐ |
| **Risk 风险**               | 有什么风险和限制？       |   ⭐⭐⭐⭐ |
| **Trade-off 权衡**          | 为什么选 A 而不是 B？   |  ⭐⭐⭐⭐⭐ |
| **Test 测试**               | 怎么验证设计正确？       |   ⭐⭐⭐⭐ |
