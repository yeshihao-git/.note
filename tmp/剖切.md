# CAE 剖切功能后端

## 1. 功能定位

剖切功能采用“前端交互预览 + 后端真实剖切”的架构。

前端不负责对多个 `.vtp` 模型逐个做真实几何切分。前端只负责收集剖切平面、当前参与剖切的组件 `blockIds`、当前云图字段 `fieldId`，然后通过 WebSocket 请求后端生成真实截面。

后端基于文档内存中的 `vtkUnstructuredGrid` 执行 `vtkCutter`，生成轻量级切面 `.vtp`，再通过二进制帧发送给前端。前端收到后将切面作为一个独立的 `sliceActor` 加入三维视口。

## 3. 前端请求协议

前端通过已有 WebSocket 连接发送 JSON：

```json
{
  "type": "generateSlice",
  "docGuid": "当前模型文档 GUID",
  "planeOrigin": [0.0, 0.0, 0.0],
  "planeNormal": [1.0, 0.0, 0.0],
  "blockIds": [1000000, 1000001],
  "fieldId": "displacement"
}
```

字段说明：

- `type`：固定为 `generateSlice`
- `docGuid`：模型打开后的文档 ID，必须与当前模型一致
- `planeOrigin`：剖切平面上一点，长度为 3 的数组
- `planeNormal`：剖切平面法向，长度为 3 的数组
- `blockIds`：可选。参与剖切的组件 ID 列表。不传或空数组时，后端默认切整个模型
- `fieldId`：可选。当前云图字段 ID。传入后，后端会尝试生成带云图标量的切面
- `resultPaths`：可选。一般不需要前端传；除非后续由前端显式指定云图文件路径

兼容字段：

- 后端同时兼容 `origin` 作为 `planeOrigin` 的别名
- 后端同时兼容 `normal` 作为 `planeNormal` 的别名

## 4. 多组件剖切规则

前端应根据当前交互状态生成 `blockIds`：

- 如果用户选中了若干组件：只传这些组件对应的 `blockIds`
- 如果用户没有选中组件：建议传当前几何可见组件的所有 `blockIds`
- 如果某组件在结构树中几何隐藏：不应参与剖切
- 如果云图关闭：不传 `fieldId`
- 如果云图开启：传当前活动云图字段 `fieldId`

注意：后端返回的是这些组件合并后的一个切面 VTP，不是多个组件各返回一个 VTP。前端显示时可以先按一个整体 `sliceActor` 处理。

## 5. 后端返回文本消息

### 5.1 切面元数据

```json
{
  "type": "sliceResult",
  "docGuid": "当前模型文档 GUID",
  "slice": {
    "pointCount": 1024,
    "cellCount": 512,
    "bounds": [0, 1, 0, 1, 0, 1]
  },
  "field": {
    "fieldId": "displacement",
    "name": "displacement",
    "label": "displacement",
    "category": "displacement",
    "association": "point",
    "rangeReady": true,
    "min": 0.0,
    "max": 1.0,
    "valueCount": 10000
  },
  "planeOrigin": [0.0, 0.0, 0.0],
  "planeNormal": [1.0, 0.0, 0.0]
}
```

说明：

- `field` 只有在请求传入 `fieldId` 且后端绑定成功时返回
- `cellCount = 0` 表示剖切平面没有切到模型，前端应显示为空切面，而不是当成异常

### 5.2 切面完成

```json
{
  "type": "sliceFinished",
  "docGuid": "当前模型文档 GUID"
}
```

### 5.3 切面错误

```json
{
  "type": "sliceError",
  "error": "错误信息"
}
```

## 6. 切面二进制协议

后端会在 `sliceResult` 后发送一个二进制帧，帧头魔数为 `SLCE`：

```text
int32 magic            = 0x534C4345  // "SLCE"
int32 docGuidLength
int32 fieldIdLength
int32 sliceBytesLength
int32 flags            // 当前保留，值为 0
byte[] docGuidUtf8     // 4 字节对齐
byte[] fieldIdUtf8     // 4 字节对齐，可为空
byte[] vtpBytes        // vtkXMLPolyDataReader 可直接解析的 VTP 二进制内容
```

注意：

- Java `ByteBuffer` 默认使用大端序，前端 `DataView.getInt32(offset)` 不传 littleEndian 即可
- `docGuidUtf8` 和 `fieldIdUtf8` 后面有 4 字节补齐，需要用 `align4(length)` 计算偏移
- `vtpBytes` 是完整 `.vtp` 文件内容，前端使用 `vtkXMLPolyDataReader.parseAsArrayBuffer(...)` 解析

前端解析伪代码：

```js
const SLICE_BINARY_MAGIC = 0x534c4345;

function align4(value) {
  return (value + 3) & ~3;
}

function routeSliceBinary(rawData) {
  const view = new DataView(rawData);
  const magic = view.getInt32(0);
  if (magic !== SLICE_BINARY_MAGIC) return false;

  const docGuidLength = view.getInt32(4);
  const fieldIdLength = view.getInt32(8);
  const sliceBytesLength = view.getInt32(12);

  const docGuidOffset = 20;
  const fieldIdOffset = docGuidOffset + align4(docGuidLength);
  const vtpOffset = fieldIdOffset + align4(fieldIdLength);
  const vtpBuffer = rawData.slice(vtpOffset, vtpOffset + sliceBytesLength);

  const polyData = VTPReader.ReadFromBuffer(vtpBuffer);
  return { polyData };
}
```

## 7. 前端显示方式

前端显示切面时建议使用独立 actor：

```text
model actors     原始模型/组件 VTP actor
edge actors      原始边线 actor
contour actors   原始云图 actor
sliceActor       后端返回的真实剖切截面 actor
```

也就是说，剖切结果不是修改原有组件 actor，而是新增或替换一个 `sliceActor`。

推荐流程：

1. 用户拖动剖切面时，前端可先用 vtk.js clipping plane 做外壳实时预览
2. 鼠标释放或点击确认后，防抖发送 `generateSlice`
3. 收到 `sliceResult` 后记录本次请求的元数据
4. 收到 `SLCE` 二进制后解析 VTP，生成或替换 `sliceActor`
5. 如果已有旧 `sliceActor`，删除旧 actor、mapper、polyData，避免显存泄漏
6. 如果返回的切面带标量数组，mapper 开启 `scalarVisibility` 并使用当前图例色标

## 8. 前端需要补充的工作

当前前端还需要补以下内容：

- 在 `MessageRouter` 中识别 `SLCE` 二进制帧
- 增加 `requestSlice(...)` 或类似服务方法，发送 `generateSlice`
- 在 viewer 层维护 `sliceActor`
- 支持替换/清除当前切面
- 从结构树可见性状态中收集参与剖切的 `blockIds`
- 与云图状态联动：云图开启时传 `fieldId`，关闭时不传
- 拖动剖切面时增加防抖，避免高频请求后端
- 可选：拖动中使用前端 clipping plane 做临时视觉反馈，后端切面只在停止拖动后生成

## 9. 后端剩余工作

当前后端可以支撑前端第一版接入，但后续工业级完善还需要：

- 增加 `requestId` 或 `sliceId`，避免多次剖切请求返回乱序时前端显示旧切面
- 将剖切改成任务化 `sliceJob`，适配大模型耗时剖切
- 扩展云图绑定策略，支持 `CellData`、单元应力、积分点结果、壳单元上下表面结果
- 明确空切面语义：`cellCount = 0` 应作为成功返回，而不是错误
- 支持多平面、双面、三面、盒剖切
- 后续 Worker 化时，将 `CaeSliceEngine` 移到 Worker 进程或独立服务中

## 10. 当前限制

- 当前剖切只支持单平面
- 当前云图剖切主要支持节点标量 `PointData`
- 壳单元模型剖切可能得到线，而不是实体内部填充面，这是由模型本身数据类型决定的
- 如果模型只有外壳表面，没有实体体网格，后端无法凭空生成真实内部实体截面
- 当前尚未做切面请求乱序保护，前端接入时建议先加本地请求序号过滤

## 11. 调试建议

前端可先用最小请求测试：

```json
{
  "type": "generateSlice",
  "docGuid": "当前 docGuid",
  "planeOrigin": [0, 0, 0],
  "planeNormal": [1, 0, 0]
}
```

确认收到：

```text
sliceResult -> SLCE binary -> sliceFinished
```

再逐步加入：

```json
{
  "blockIds": [1000000, 1000001],
  "fieldId": "displacement"
}
```

如果 `sliceResult.slice.cellCount = 0`，优先检查剖切平面是否穿过模型包围盒，以及 `blockIds` 是否包含当前模型真实存在的组件。
