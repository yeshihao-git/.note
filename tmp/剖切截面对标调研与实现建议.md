# WebCAE 剖切、切面与截面对标调研及实现建议

## 1. 结论先行

“剖切”“切面”“截面”在中文 CAE 软件中经常混用，不宜把名称本身当作严格的技术定义。为避免前后端与客户沟通歧义，WebCAE 应按**用户意图与数据产物**区分，而不是按口头名称区分。

| 推荐术语 | 明确定义 | 结果是否是新数据对象 | 本期实现位置 |
| --- | --- | --- | --- |
| 剖切平面 | 控制对象，定义 `origin + normal + reverse` | 否 | 前端交互状态 |
| 浏览剖切（Clip Preview） | 隐藏平面一侧的已渲染几何，用于快速观察 | 否 | 前端 GPU 裁剪 |
| 截面结果（Section / Slice Result） | 体网格与平面的真实交集，输出二维网格、边线及结果值 | 是 | 后端 VTK 计算 |
| 实体裁切（Persistent Clip） | 保留平面一侧的体单元，必要时生成截断面 | 是 | 后端，后续能力 |

UI 中不建议只写“切面”。建议工具主入口命名为“剖切”，面板中使用“剖切平面”“截面结果”“反向”“显示截面”等精确名称。

## 2. 对标软件结论

### 2.1 Tecplot 360

Tecplot 将 Slice 作为派生对象：平面与体 Zone 相交后生成 Slice。它提供 X/Y/Z 主平面、任意平面、三点定义平面、原点和法向输入；任意平面可拖动平移手柄、法向手柄和旋转中心。Slice 可以独立控制网格、云图、着色、透明度、边线，并支持起止位置之间生成多张中间 Slice 和动画。[Tecplot Slice 交互说明](https://tecplot.com/2021/08/05/placing-a-slice/)

Tecplot 对结果位置有明确语义：

- 节点结果：交点结果沿源单元边线性插值。
- 单元中心结果：默认保留到生成 Slice 的单元上；若显示方式要求节点值，可从周围单元值导出节点值。
- 也就是说，软件不会把“平滑显示”与“真实单元结果”混为一谈。[Tecplot 场值派生说明](https://kb.tecplot.com/2019/06/06/derivation-field-values-slices-iso-surfaces/)

### 2.2 ParaView / VTK

ParaView 明确分离两类操作：

- `Clip`：对三维数据集按隐式函数保留一侧；被平面穿过的单元会被真正裁切，输出仍是三维非结构网格。支持 `Inside Out` 反向；`Crinkle Clip` 则不切单元，保留与区域相交的完整原始单元。
- `Slice`：只返回隐式函数边界上的降维结果。对四面体、六面体等三维单元，输出二维三角形或四边形；对二维单元，输出线。

这正是 WebCAE 应采用的概念边界。[ParaView Clip 与 Slice 文档](https://docs.paraview.org/en/v5.10.1/UsersGuide/filteringData.html)

VTK 层的对应基础算法为：

- [`vtkCutter`](https://github.com/Kitware/VTK/blob/master/Filters/Core/vtkCutter.cxx)：将 N 维单元与隐式函数相交，产生 N-1 维几何；平面切四面体会生成三角形。
- [`vtkClipDataSet`](https://github.com/Kitware/VTK/blob/master/Filters/General/vtkClipDataSet.cxx)：保留裁切后的一侧体单元；为保证单元邻接兼容性，可能将三维单元三角化为四面体。

## 3. 四面体模型：为什么会“凹凸不平”

### 3.1 几何结论

对**线性四面体网格**使用同一个数学平面切割时，每个交点都在该平面上，生成的截面三角形也共面。因此“真实平面截面”在几何上不应凹凸不平。

用户看到的棱角、色块或不连续，通常来自以下不同原因：

| 现象 | 根因 | 是否应该自动平滑 |
| --- | --- | --- |
| 截面网格边界呈三角片 | 有限元离散和三角化显示 | 可隐藏边线或使用平滑法线，仅改变视觉 |
| 相邻区域颜色突变 | 单元中心结果，物理上允许不连续 | 默认不平滑 |
| 云图色带呈三角片渐变 | 节点结果按单元形函数线性插值 | 正常现象，无需积分 |
| 截面几何真的不共面 | 使用曲面/非线性单元近似、平面参数误差或错误重建 | 应检查数据和算法，不应用视觉平滑掩盖 |

### 3.2 “插值”和“积分”不是同一件事

截面求交不需要数值积分。对于节点标量，交点值由单元边上的形函数插值获得；线性四面体可理解为沿相交边的线性插值。对于单元中心标量，截面单元直接继承母体单元值即可。

如需将单元中心应力显示为连续颜色，需要额外做“单元到节点投影/节点平均/应力恢复”。这会改变显示数据，必须：

1. 显式提供“原始单元值 / 节点平均值”选项；
2. 在图例或结果元数据中标明 `association=cell` 或 `association=point`、`derived=true/false`；
3. 不把显示平滑误称为原始求解结果。

原型阶段建议只保证原始节点值插值和原始单元值继承；不引入通用平滑、积分或应力恢复算法。

## 4. 当前 Intevue 实现评估

### 4.1 已具备的正确基础

- `CaeSliceEngine` 使用 `vtkCutter + vtkPlane`，输出二进制 VTP；可按 `blockIds` 过滤组件。这与“真实截面结果”的正确算法方向一致。
- `IntevueLib::GenerateSlice` 已接收 `docGuid`、平面原点/法向、组件范围和结果场标识。
- `ResultDataExtractor::BindScalarFieldToVolume` 将节点标量绑定到 `volumeGrid` 的 PointData；`vtkCutter` 可在生成截面时对节点结果进行插值。
- Java WebSocket 已有 `generateSlice`、`sliceResult`、`SLCE` 二进制帧及 `sliceFinished` 消息链路。

相关代码：

- [CaeSliceEngine.cpp](/E:/code/IntevueServer/IntevueCAE/foundation/IntevueCAE/src/CaeSliceEngine.cpp)
- [IntevueLib.cpp](/E:/code/IntevueServer/IntevueCAE/foundation/IntevueCAE/src/IntevueLib.cpp)
- [ResultDataExtractor.cpp](/E:/code/IntevueServer/IntevueCAE/foundation/IntevueCAE/src/ResultDataExtractor.cpp)
- [InteCAEWebSocket.java](/E:/code/IntevueServer/IntevueCAE/backend/src/main/java/com/intecae/websocket/InteCAEWebSocket.java)

### 4.2 当前缺口与风险

1. 当前 `BindScalarFieldToVolume` 仅按 `valuesByNodeId` 构造 PointData。若“Element Stress”实际是单元中心数据，截面结果的数据关联和渲染语义尚需独立实现，不能误按节点值处理。
2. 当前 Web 前端的 `切面` 工具是入口状态，尚未接入平面交互、实时裁剪或 `generateSlice` 消息处理。
3. 当前浏览器加载的是组件外表面 VTP。仅在前端裁剪外壳时，能够看到“切掉一半”，但不会生成实体截断面，也不能可靠展示内部云图；真实内部截面必须使用后端体网格计算。
4. `ExtractBlocks` 当前每次截面请求遍历所有单元筛选 `BlockId`。大模型下应在文档打开后缓存 `BlockId -> CellId 列表`，避免每次截面重复全量扫描。
5. 截面 VTP 为独立派生对象，应具备 `sliceId`、输入平面、源结果场、源组件集合、创建时间和释放策略，避免多次拖动产生无界临时文件。

## 5. 推荐交互流程（第一期）

### 5.1 用户流程

```text
点击“剖切”
  -> 默认创建一个 X/Y/Z 方向剖切平面
  -> 拖动平移手柄或输入距离
  -> 前端对全部可见组件做 GPU 裁剪预览
  -> 切换“反向”时立即翻转保留侧
  -> 用户松开手柄或点击“生成截面”
  -> 后端按当前平面和组件范围生成真实截面
  -> 前端叠加显示截面网格/云图
  -> 关闭剖切：清除预览；可选择保留或删除截面结果
```

### 5.2 建议页面

在现有右侧工具栏的“剖切”入口下展开一个紧凑属性面板，不新增横向工具按钮。

| 控件 | 第一期行为 |
| --- | --- |
| 模式 | `浏览剖切`、`截面结果` 两个开关；后者按需生成/刷新 |
| 平面方向 | X / Y / Z / 任意；第一期任意平面只预留数据结构或支持法向输入 |
| 平面位置 | 沿法向滑块 + 数字输入；拖动控制手柄同步更新 |
| 反向 | 翻转保留侧 |
| 作用范围 | 全部可见组件；后续可扩展为当前选中组件 |
| 截面显示 | 显示/隐藏、云图/纯色、边线显示 |
| 重置 | 关闭预览并清理当前截面 |

不要在第一期加入多平面组合、盒剖切、捕捉曲面/圆柱轴、截面测量、截面导出或动画扫切。它们可以保留为后续扩展方向。

### 5.3 与 `master_v1_vuejs` 的取舍

旧项目已有单/双/三平面、盒剖切、反向、参考点/面/圆弧/圆柱等丰富交互，参考入口包括：

- [Clipping.vue](/E:/code/master_v1_vuejs/src/components/Toolbar/Clipping/Clipping.vue)
- [ClippingPanel.vue](/E:/code/master_v1_vuejs/src/components/panel/ClippingPanel.vue)
- [HIOpClippingBaseOp.js](/E:/code/master_v1_vuejs/src/appCore/Operate/Clip&Explosion/HIOpClippingBaseOp.js)

它适合作为交互经验参考，但不应整体搬迁：其实现与 Three.js 全局控制器、命令消息总线和业务 UI 强耦合。当前 Vue + Pinia + vtk.js 原型应重新建立轻量的 `SliceStore`、`SlicePreviewController` 和 `SliceResultService` 边界。

## 6. 推荐前后端边界

### 前端：只做即时交互与显示

- 维护 `sliceId / origin / normal / reverse / enabled / scope`。
- 对当前已加载的所有组件 Actor 应用同一 GPU 裁剪平面，作为拖动期间的低成本预览。
- 拖动停止后使用防抖（建议 300 至 500 ms）请求后端截面；请求需带 `requestId`，只渲染最新响应。
- 截面结果作为独立 Actor 集合管理，可独立切换显示、边线、透明度和云图。
- 不在浏览器重建体网格、拼接组件截面或从 CSV 计算插值。

### 后端：只做派生数据计算

建议请求合同：

```json
{
  "type": "generateSlice",
  "docGuid": "...",
  "sliceId": "slice-1",
  "requestId": "...",
  "planeOrigin": [0, 0, 0],
  "planeNormal": [1, 0, 0],
  "blockIds": [101, 102],
  "fieldId": "stress",
  "association": "point"
}
```

后端职责：

- 校验文档、平面、组件范围和结果场的数据关联。
- 节点结果：绑定 PointData 后由 `vtkCutter` 插值。
- 单元结果：绑定 CellData，并将输出标记为 `association=cell`；不默认做节点平均。
- 输出独立截面几何和元数据，发送二进制帧；支持取消过期请求、替换同一 `sliceId` 的旧缓存和清理临时文件。

## 7. 7 月 30 日可验收范围

建议将验收控制在一个可稳定演示的闭环：

1. 单一 X/Y/Z 剖切平面，可平移、反向和重置；作用于所有可见组件。
2. 前端拖动期间视觉裁剪流畅，不向后端连续发起重算。
3. 鼠标释放或点击“生成截面”后，后端输出一个真实截面结果并叠加显示。
4. 节点云图可在截面上正确连续插值；单元云图至少可明确显示为单元常量，不做伪平滑。
5. 结构树显隐与截面范围一致；隐藏组件不会参与后续新截面计算。
6. 至少使用一个含四面体实体单元和一个节点云图字段的客户样本验收，并保存平面参数、截图和对标结果。

## 8. 后续扩展顺序

1. 第二阶段：任意平面旋转、已选组件范围、多截面列表、结果缓存和截面边线。
2. 第三阶段：盒剖切、多平面组合、Crinkle 模式、截面探针与二维曲线。
3. 第四阶段：单元到节点投影/应力恢复（需与求解器结果语义和客户验收口径共同定义）。
